# Generated, copied and vendored files

App repositories hold a lot of code nobody edits by hand: web builds copied into native projects (Capacitor,
Cordova), framework build directories (`.nuxt/`, `.next/`), generated API clients (OpenAPI, protobuf / gRPC) and code
generators' output (Flutter / Dart `build_runner`, the Flutter plugin registrants). cg recognises these files, keeps
them out of the graph by default and lists them in `cg coverage`. Answers stay short and point at the files you
actually change, and each copy maps back to its source.

## How a file is recognised

One classifier (`codegraph/core/generated.py`) runs during the file scan at the start of `cg index`. Every language
plugin, the TypeScript and Dart extractors and the coverage scan consult it, so each file gets the same answer
everywhere. The first matching rule wins:

| rule | classification and reason |
|---|---|
| `.cg.yaml` `generated.keep` globs | never classified (hand-maintained files a rule below would catch) |
| `.cg.yaml` `generated.paths` / `generated.vendored` globs | generated / vendored |
| `.gitattributes` (any directory) `linguist-generated`, `linguist-vendored` | generated / vendored. Git's precedence applies: a deeper file and a later line win. `-attr` / `attr=false` marks a file as hand-written, and `!attr` returns it to detection |
| Capacitor: `webDir` from `capacitor.config.(ts\|js\|json)` | `android/app/src/main/assets/public/` and `ios/App/App/public/` are **copied** from `webDir`, with `copy_of` per file. `cap sync` output (`capacitor.config.json` / `capacitor.plugins.json` copies, `config.xml`, the `capacitor-cordova-*-plugins` projects) is generated. `webDir` itself is web build output when its directory's `.gitignore` lists it or `angular.json` builds into it |
| Cordova: `config.xml` with `<widget>` | `platforms/<platform>/www/` (and `app/src/main/assets/www/`, `platform_www/`) is **copied** from `www/` |
| `.openapi-generator/FILES` | every file it lists, relative to the generator's output directory |
| framework build directories (any depth) | `.nuxt/`, `.output/`, `.next/`, `.svelte-kit/`, `.docusaurus/`. `dist/` and `build/` are skipped by every walk and listed as build output |
| generator file names | `*.g.dart`, `*.freezed.dart`, `*.gr.dart`, `*.mocks.dart`, `*.config.dart`, `generated_plugin_registrant.*`, `GeneratedPluginRegistrant.*`, Flutter `ephemeral/` directories, protoc output (`*_pb2.py`, `*_pb2_grpc.py`, `*.pb.go`, `*_pb.ts`, `*_pb.js`, `*.pb.swift`, `*.pb.cc` / `.h`, `*.pb.dart`, `*.pb.rs` ...) |
| header banner in the leading comment block | `@generated`, `Code generated ... DO NOT EDIT.` (Go convention), `GENERATED CODE - DO NOT MODIFY BY HAND` (Dart `build_runner`), `<auto-generated>` (.NET), `This file is (automatically / auto-) generated`, protoc / gRPC banners, OpenAPI Generator / Swagger Codegen banners |

Banners count only in the comment lines before the first line of code, so a docstring or string that mentions
`@generated` does not mark its file. The built-in directory and file-name lists live in
`codegraph/presets/common.yaml` (`generated`), next to the other presets.

## Default: out of the graph, listed by coverage

Generated files are not parsed, and a final pass drops any node whose file is classified, together with its edges.
The coverage scan does not count them as source of their language. `cg coverage` and the MCP `coverage` tool list
them by reason:

```text
$ cg coverage --db out/app.db        # an Ionic Angular app with Capacitor (validation.md)
coverage app: typescript 140 exact | not fully covered: java 3 unsupported | generated: 211 files excluded
  generated: 211 files excluded (copy of www/ (Capacitor webDir) 107, web build output (Capacitor webDir) 104); build output not scanned: ios/App/build/
    android/app/src/main/assets/public/ (107 files) is a copy of www/ [Capacitor webDir 'www' (capacitor.config.json)]
    www/ (104 files) is web build output (Capacitor webDir) [Capacitor webDir, angular.json outputPath]
    copy of www/ (Capacitor webDir): android/app/src/main/assets/public/1.691af87c6bbc686b487e.js, ... +102 more (--all-files)
```

The MCP `coverage(path=...)` answer for a generated file says so and names the reason, so an agent edits the source
instead.

The `cg index` stats JSON has the same count under `generated`, broken down by language (the coverage language
keys, `other` for non-source files), reason and kind, plus what the final pass did:

```json
"generated": {"files": 3, "by_language": {"typescript": 2, "dart": 1},
              "by_reason": {"OpenAPI Generator (.openapi-generator/FILES)": 2, "build_runner output (*.g.dart)": 1},
              "by_kind": {"generated": 3}, "mode": "excluded",
              "files_with_dropped_nodes": 1, "nodes_dropped": 2, "edges_dropped": 4}
```

`files` counts every classified file, including the TypeScript and Dart files the extractors skip before parsing.
`files_with_dropped_nodes` counts the files whose nodes the final pass removed (`files_with_nodes`,
`nodes_labelled` and `copy_of_edges` with `--include-generated`).

Files that serve as resolution input are still read. Nuxt's `.nuxt/` types resolve auto-imports, and `*.g.dart`
gives json_serializable's exact JSON keys (`PARSES_JSON` and the response-field check are unchanged). Their own
functions don't become nodes.

## `--include-generated`: indexed and labelled

`cg index --include-generated` (or `generated.include: true` in `.cg.yaml`) indexes the same files as before. Every
node from them carries `attrs.generated = {kind, reason[, copy_of]}`, and `impact`, `reaches` and the MCP `impact`
tool label them:

```text
$ cg impact shop.service.place --db out/py.db
callers (transitive): 3
  d=1 [shop] shop.api.create
  d=1 [shop] shop.orders_pb2.decode  [generated: protoc output (Python)]
  d=1 [shop] shop.schema.run  [generated: 'Code generated ... DO NOT EDIT.' header]
```

A copied file's module node gets a `COPY_OF` edge to the module node of its source file when both are indexed. A hit
in a copy then points at the file to edit, and the copy is not counted as a second implementation. The MCP `index`
tool keeps `--include-generated` across re-indexes.

## Project rules

```yaml
# .cg.yaml
generated:
  paths: ["src/api/generated/**"]   # generated output detection misses
  vendored: ["third_party/**"]      # vendored copies of other projects
  keep: ["src/schema.gen.ts"]       # hand-maintained files a rule would classify
  include: false                    # true: index them, labelled (same as --include-generated)
```

`cg config show` lists the built-in rules and these keys with their source.
